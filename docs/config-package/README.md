# 配置包与换机恢复

在桌面端打开「配置 → 配置来源」。导出时确认敏感信息提示，再选择仅自己可访问的保存位置。配置包是未加密的 JSON，可能包含订阅 URL、节点凭据和覆写内容。macOS 与 Linux 上，应用以 `0600` 写入新文件。Windows 上文件访问权限取决于保存目录的 ACL。

配置包包含订阅来源、缓存的配置内容、自动更新间隔、覆写链及绑定、启用状态和当前配置。导入保留目标设备的内核、端口、外观、系统代理、TUN 和授权设置。导入会合并条目并替换相同 ID 的配置。若替换某条覆写会影响包外本地配置，应用会在预览时报冲突。请导入可信来源的包。

## 换机演练

使用 [脱敏示例包](example.json)。示例订阅使用保留域名 `example.invalid`，自动更新已关闭。

1. 在独立的应用数据目录选择「导入配置包」。预览应显示新增 2 份配置及 2 条覆写，并说明会切换当前配置。第一次取消，确认现有配置没有变化。
2. 重新选择文件并确认。查看当前配置是否为 `Offline example`。重启后核对两个绑定及其启用状态，并用本机混合端口代理访问一个已知测试服务。
3. 在同一安装中先添加一份独立配置，再重复导入。预览应显示替换 2 份配置及 2 条覆写。确认独立配置仍在，原数据可以通过「配置恢复」中的写前快照恢复。
4. 修改示例副本，将某个绑定改为不存在的 ID。导入应在确认前拒绝。用独立测试目录模拟写入失败，再检查原配置、当前选择和接管状态。

## 已验证范围

在 macOS 的隔离目录完成 Rust 配置包导出、导入和重开存储。使用 mihomo 1.19.32 在回环端口启动恢复后的配置，经混合端口请求本地 HTTP 服务并拿到已知响应。测试检查了已启用覆写生效、停用覆写跳过和导入方端口保留。

本地回归覆盖同 ID 合并、无效绑定、旧 schema、超大文件、预览失效、写入失败后原文件可读取及 Unix 私有文件写入。使用生产配置页和模拟 IPC 验证了导出提示、取消、过期预览和重新确认。

真实桌面的原生文件对话框、改机后的系统代理与 TUN 接管恢复，以及 Windows 和 Linux 宿主的完整换机演练仍需验收。
