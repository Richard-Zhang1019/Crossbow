# 节点分项测试（#604）

入口：**节点 → 质量历史 → 分项测试**。选择内联具体节点，按需开始连通性或有界吞吐。
查看、切换类型、刷新本地历史都不会自动测试。测试期间可取消；关闭面板也会取消。

## 产品含义

- **TCP 隧道**：通过所选节点建立到 `speed.cloudflare.com:443` 的 TCP 隧道。
  不是直接连接代理服务器端口的 ping，也不证明 TLS/HTTP 可用。
- **HTTPS**：另一次经过该节点、校验证书的 Cloudflare HTTPS 请求（`__down?bytes=0`）。
  TCP 成功但 HTTPS 未验证可分别展示；HTTPS 未验证包含 TLS/目标响应问题，不推断永久节点故障。
- **UDP DNS**：SOCKS5 UDP ASSOCIATE 经所选节点向 `1.1.1.1:53` 发送固定 `example.com A`
  请求，至多 3 个数据报。验证中继来源、目标地址/端口、分片标记、事务 ID、问题和 DNS 响应。
  没有有效响应只标为“未验证”；HTTP 节点、显式禁用 UDP 等情况标为不支持，不把未测当作失败。
- **有界吞吐**：Cloudflare 固定下载/上传端点，最多下载 **4 MiB**、上传 **1 MiB** 测试正文。
  这是有效载荷上限；加密、连接、DNS、响应、重传及套接字缓冲开销另计，不是流量账单硬上限。
  界面在开始前提示可能消耗订阅流量。短正文/中断不计算成功速率；上传未获确认时实际发送量未知。
  速率包含连接和目标响应开销，只代表本次端到端有效吞吐，不能解释为线路带宽上限。

整次任务最多 **30 秒**（隔离内核准备最多 5 秒；TCP 5 秒、HTTPS 7 秒、UDP 4 秒，
下载 8 秒、上传 6 秒分别也有阶段预算）。各类型只运行对应阶段，不为了补齐表格自动发包。
进程启动前再次检查预算；取消/配置代变化可终止阻塞中的请求。一个应用进程同时只运行一个
分项任务，且与节点页延迟批次互斥。取消回收期间不能立即创建第二个任务。

## 最佳方案与实际范围

通过当前混合端口测量只能反映当时实际路由；直接变更当前策略又会影响用户连接。
**最佳方案**：从当前内核已应用配置中取出所选具体节点及其拨号依赖，生成临时最小配置，
以同一内核二进制启动独立测试实例。它不修改当前内核、策略、系统代理、TUN、DNS 或路由。

支持内联常见代理和至多 16 层无环拨号链，保留原协议参数；策略组、provider-only 节点、
WireGuard/Tailscale/其他可能管理主机网络或启动常驻工作的类型明确拒绝，不静默改测当前出口。
依赖策略组或未展开 provider 的拨号链也不支持。运行配置上限 16 MiB。
隔离配置不复制用户入站、TUN、规则集、远程 provider、自动健康检查或外部控制器。
Mihomo 只创建私有单成员选择组用于避免节点名中的逗号被解释为规则 CSV；它不会自动选路。

隔离实例使用**系统 DNS**，不等同于当前内核的自定义 DNS。主机上已有的 TUN/VPN、
路由、其他代理客户端和网络拥塞也可能影响测试路径；不能由此推断公网物理出口。
测试只展示观测，不改变节点可用性标记、卡片主目标延迟或自动选路权重。

## 进程、隐私和历史

使用随机回环端口及一次性认证，只经认证 SOCKS5 连接测试实例，不读取环境代理。
HTTPS 复用 ureq 的证书验证、HTTP 分帧与请求截止时间，保留默认证书校验且不跟随重定向。
临时配置中必要的节点凭据仅写入私有目录（Unix `0700`，文件 `0600`）；不写日志、不上传。
临时内核的 stdout/stderr 不进入正式日志或错误通知，失败提供静态脱敏原因。

独立守护模式 `--crossbow-node-probe-worker` 在 Tauri/单实例/网络恢复逻辑之前运行。
GUI 持有的管道关闭（含 GUI 崩溃）或达到 30 秒后，守护程序 kill/wait 自己创建的内核，
清理经过验证的私有临时目录。Unix 使用独立进程组兜底；Windows 守护程序在启动子进程前
加入带 kill-on-close 的私有 Job。只结束本次拥有的进程，不根据名字或端口查杀其他客户端。

结果复用 `node-quality.json` 的配置/节点哈希隔离、暂停/清空代保护、私有原子写入和 7 天保留期。
分项报告全局最多 **128 条**，每次查询显示某节点最近 **6 条**；与 8192 条延迟样本分别限额，
同受文件 2 MiB 上限约束。只保存分类、时间、数据报数、已确认正文量和速率，不保存节点名、
订阅地址、凭据、错误原文或任意目标。旧版本历史缺少分项字段时按空集合读取。

取消和失效配置不发布新报告；完整/部分结果带各自状态与时间，不用旧数据冒充当前结果。
任务完成后释放有效性检查的 AppHandle 引用；进度和失败共用统一通知的 task operationId。
状态读取失败时界面保留未知/进行中状态并允许重读，不假定后端已经停止。开始请求尚未返回时
点击取消，会在拿到任务票据后立即取消；迟到结果不覆盖新的节点或已关闭面板。

## 验证与边界

- 单元/回归：数据包校验、下载上限/短正文、预算/取消、最小配置清洗、拨号链与私有目录边界，
  分项历史容量/隔离/暂停/清空/落盘，失败任务的引用释放和重入。
- `scripts/dev/verify-node-probes.mjs`：真实 React + 脱敏 IPC；覆盖显式开始、分项呈现、负载提示、
  部分上传、开始票据迟到后取消、状态读取失败重试、清空、关闭取消、明暗/中英文/小窗口。
  旧 `verify-node-quality.mjs` 同时回归延迟历史。两类脚本均纳入 CI。
- `docs/designs/2026-11-22-node-probes/v01/verification/native.py`：真实 mihomo/sing-box 受控
  TCP 成功/HTTPS 失败、HTTP 成功/UDP 黑洞、GUI 父进程被终止后的回收，以及固定公网分项测试。
  另有独立 DIRECT-only 显式代理业务探针记录前/同期成功率、P50/P95 和实际重叠请求数。
  使用内联脱敏夹具，不读取用户订阅，不修改主机网络设置。
- 原生检查在 macOS 执行；不是原生窗口/Tauri IPC 的完整产品验收。Windows Job 与 Linux
  平台代码仍需对应 CI 构建和实机确认。小样本性能数据不证明普遍“零干扰”。
