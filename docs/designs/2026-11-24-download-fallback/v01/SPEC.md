# #655 下载页版本信息：10 分钟缓存与失败提示样式 · v01

日期：2026-11-24 · 关联 issue：#655 · 状态：已实现，待 PR 评审

## 问题

下载页版本卡片在浏览器请求 GitHub Releases API：

1. 每次进入页面都请求（未认证额度 60 次/小时/IP），公共预览和反复刷新容易命中限流，失败时立刻弹出「当前展示的是缓存的版本信息（本次刷新失败）」。
2. 失败提示是粗边框 + 下划线重试链接的风格，和页面其它提示不一致；无缓存和有缓存两种失败混用同一文案层级。
3. 顺带发现：某平台缺少安装包时按钮文案引用未定义的 `_()`，失败态会整块渲染崩溃（主分支同样存在）。
4. 附带：组件在渲染期直接读 localStorage 决定初始状态，服务端 HTML 与客户端首帧不一致，React 每次都会报 #418/#423 hydration 警告（主分支同样存在）。

## 方案

- **缓存 TTL 10 分钟**：`readCache()` 返回 `{ info, fresh }`；首屏从缓存水合，缓存新鲜（<10 分钟）时**不发请求**；过期后才刷新。手动「重试」不受 TTL 限制。
- **请求容错**：8 秒超时（`AbortController`）+ 一次 1.5 秒后的静默重试；仍失败才回退缓存/失败态。
- **提示样式**：改为单行内联提示——信息图标 + 说明文字 + 右侧小号描边「重试」按钮，边框/底色沿用页面 `--line`/`--surface`，明暗主题都保持低对比。 提示条与下载卡片同宽（`max-width: 1240px` 居中），下留 20px 与卡片区隔；窄屏跟随单列卡片（560px）。
- **崩溃修复**：缺失安装包时按钮文案改为按语言输出，不再引用未定义的 `_`。
- **水合修复**：首帧固定为 loading，挂载后再从缓存水合并决定是否请求，服务端与客户端首帧一致，不再新增 hydration 警告。

## 证据

- `scripts/dev/verify-site-download.mjs`（生产静态构建 + Chromium，拦截 api.github.com）：
  - 缓存 2 分钟 + API 失败：**0 次请求**、无提示、展示缓存版本；
  - 缓存 60 分钟 + API 失败：2 次请求（首查 + 重试）、展示缓存版本 + 提示条；
  - 无缓存 + API 失败：失败提示 + 三个平台按钮仍指向发布页；
  - API 成功：无提示、展示最新版本；
  - 无未预期的页面错误（仅保留主分支既有的 React hydration 警告）。
- 截图：`previews/before-notice.png`（主分支旧样式，14px 粗边 + 下划线链接）、`after-notice-light.png`、`after-notice-dark.png`、`after-failed.png`、`after-fresh-cache.png`。
- `verification/build.log`（含 8 项站点测试）与 `verify.log` 通过。

## 未覆盖

- 真实 GitHub 限流（403）与网络超时的实机复现；CI 无外网访问 GitHub API 的稳定条件，脚本用请求拦截模拟。
- 下载页 React 岛的既有 hydration 警告（#418/#423）来自 #363/#649 的历史实现，本次只保证不新增；彻底消除需要把整个岛改为挂载后再渲染。
