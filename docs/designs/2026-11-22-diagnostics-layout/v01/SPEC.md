# 诊断页：本次结果与辅助排查 v01

状态：已实现；本地构建与生产组件模拟检查通过，待原生窗口及 CI 验收。关联 #633。

## 用户目标与根因

进入诊断页能直接开始检查；展开故障证据、上一条记录或 DNS 后，主要操作仍完整可达，内容按一个方向自然阅读。

改前基线 `fa13061f8a737e4d7879b7bea2f99527032342a7`。生产组件夹具复现：默认 1120×734 全部展开时，主按钮中心位于 y=711，超过内容区底边 y=695；最小 880×560 时按钮中心 y=606，超过窗口底边，均无法命中点击。故障卡位于滚动区外、`flex:none`，详情另按窗口 vh 限高，下方滚动区又强制最小 150px，多处高度预算相互冲突。原始几何数据见 `verification/before.json`。

## 方案评估

| 方案 | 回归面 / 复杂度 | 决定 |
| --- | --- | --- |
| 最小修复：继续压缩故障详情的 max-height，并降低下方 min-height | 代码少；仍需维护多份高度预算，长英文、历史二次展开容易再次出错；保留嵌套滚动 | 不采用 |
| 结构修复：页头固定动作，所有可变高度内容共用一个滚动区 | 只调整本页结构和样式；沿用公共 PageHead/Button、现有 IPC、诊断和 DNS 生命周期 | **最佳方案，采用** |
| 宽屏固定主辅双列、小屏切换单列 | 两套阅读顺序，故障三列表格在窄辅栏中换行严重，增加高度约束 | 本轮不引入 |

## 设计决定

沿用 Crossbow 的 Frame Studio 外壳、主题色、四级字号和公共控件。知识库以新极简/网格的清晰层级为主、开发工具的语义状态为辅；`design-taste-frontend` 选择 framed-sheet（seed 266936375，保留 palette/type），不重做已有导航或品牌。最重要的问题是“现在这次检查是否需要处理”，最大状态文字回答本次结果；历史采样只提供背景证据。

| 改前 | 改后 | 原因 |
| --- | --- | --- |
| 开始按钮在中央大空态中，运行后又迁往状态带 | 页头右侧常驻开始/重新检查及摘要入口 | 主操作位置稳定，展开不影响可点击性 |
| 历史故障在本次任务前，状态和时间挤成单行 | 本次诊断在前；辅助排查在后，标题/时间两层，长内容自然折行 | 区分本次结果与历史证据，避免截断 |
| 故障详情内滚、下方另有滚动且保底高度 | 仅 `.cb-diag-scroll` 负责页面内容纵向滚动，`min-height:0` | 按真正可用空间布局，消除竞争高度预算 |
| 巨大居中空态、图标圆底与多处重复引导 | 紧凑边框引导块，无自有主按钮 | 折叠态就能看到两项辅助工具，保持自然内容密度 |
| 空态/结果分支各挂载 DNS | 同一个 DNS 组件一直保留 | 运行主诊断不清空 DNS 草稿、展开状态和本次会话历史 |

- 点击主诊断操作时，内容区回到本次结果顶部；不移动键盘焦点、不引入平滑滚动动画。
- 页头在默认/最小窗口仍显示完整公共按钮；进行中禁用重复诊断，首次失败也明确显示未完成及重试入口。
- 主探针、独立复核、时间戳、上一条记录、恢复探针和导出白名单不变。独立复核成功不能覆盖原始失败；辅助说明明确记录反映采样时刻。
- 故障状态/通知、诊断运行标识、过期与修复保护、DNS 查询/取消/失效保护沿用现有逻辑。不访问真实订阅或修改用户系统代理/TUN。
- 本页摘要继续复用现有 Dialog；统一 Modal 组件的迁移由 #631 单独处理。

## 生产预览与复跑

已安装仓库依赖及本机 Chrome/Chromium，使用 Node 24（CI 为受支持的 Node 版本）：

```sh
npm run build --prefix apps/desktop
node --test $(rg --files apps/desktop/src -g '*.test.mjs')
CB_DIAG_EVIDENCE=/tmp/crossbow-diagnostics node scripts/dev/verify-diagnostics-layout.mjs
node scripts/dev/verify-scenarios.mjs --scenario 3
node scripts/dev/verify-dns-probe.mjs
```

- 新夹具覆盖 880×560、1120×734、1440×960 × 中英文 × 明暗 × 故障/上一条/DNS 的 8 种展开组合，另覆盖 560–960 连续高度取样、无报告、运行中、有失败/全通过结果、过期、首次失败、历史读取失败/无记录、长错误/接口名、键盘展开、DNS 表单试点击及草稿保留。
- 回归检查采用 bounding rect、`elementFromPoint` 命中、内滚动归属和内容溢出检查；原诊断场景另验证摘要脱敏和过期复检；DNS 原场景验证错误、查询结果、取消及上下文失效。脚本已登记两个 CI 桌面验证入口。
- 截图为 macOS arm64 / 系统 Chromium、实际 React 生产组件、隔离 IPC 夹具。所有浏览器外部请求被拦截；页脚 `0.14.4-verify` 是通用夹具标识，不是本次发布版本。改前在生产文件修改前保存，改后直接渲染工作树源码；manifest 的 SHA256 固定交付内容。
- 改前/改后使用相同故障模型：经代理 HTTPS 主探针超时、独立复核成功，但没有恢复探针，仍为“进行中”。不存在把截图状态美化为通过。
- 通用网页检查器未接入本项目的隔离 IPC 数据入口，使用仓库生产组件 harness 检查桌面实际支持尺寸；不对 390px 手机布局作验收声明。
