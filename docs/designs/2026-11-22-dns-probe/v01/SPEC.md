# #603 DNS 解析路径诊断 · v01

日期：2026-11-22 · 关联 issue：[#603](https://github.com/Richard-Zhang1019/Crossbow/issues/603) · 状态：已实现，待 PR 评审

## 要解决的问题

节点延迟正常、但某个网站打不开时，现有诊断只给出「系统直连 DNS 能不能解析」。
这和内核实际处理业务流量时的解析不是一回事：内网域名、hosts、节点域名引导、
代理 DNS 上游或规则都可能让两条路径得出相反结论。用户需要一次主动检查，
看到**系统解析**与**内核真实业务解析**各自的结论、耗时和失败类别。

## 入口与交互

- 诊断页底部新增一张默认折叠的卡片「DNS 解析路径」，标题行显示上一次检查的
  域名、记录类型、时间与结论状态标；未检查时显示能力说明。
- 展开后：测试域名输入 + A/AAAA 选择 + 「检查解析」按钮。只在点击时查询一次，
  不做后台轮询、不随页面加载自动发起。
- 结果区并列两条路径（系统解析 / 内核解析），每行给出状态、往返耗时、应答地址
  与 TTL，失败时保留后端给出的具体原因（例如「内核返回 RCODE 3」）。
- 结论行直接说清哪条路径失败，并给出**不越界**的提示：例如「系统能解析、内核失败」
  只说明常见原因，不断言站点或节点故障。
- 已知无法取得的事实（上游服务器、缓存命中、内核内部耗时）固定展示为「未知字段」，
  不把 TTL 当缓存命中证据，也不把控制器往返时间称作纯解析耗时。
- 历史仅保留本次会话最近 5 条，可点击回看、可一键清除；结果不落盘、不发送遥测。
  「复制结果」导出白名单摘要（域名、记录类型、时间、两条路径结论、未知字段），
  不含配置内容、控制器端口或凭据。

## 布局决定

- 卡片与诊断检查列表共用**同一个滚动区**（`.cb-diag-scroll`）。此前列表是唯一滚动区，
  在 880×560 下展开卡片会盖住空状态 CTA；改为外层统一滚动后，两种窗口高度都不会互相覆盖，
  也不再出现嵌套滚动条。
- 卡片样式类使用 `cb-dnsprobe-*` 前缀，避免与 #598 DNS 设置卡的 `cb-dns-*` 冲突
  （首次实现时 `.cb-dns-actions` 撞名导致按钮被右对齐，已修正）。

## 数据来源

| 路径 | 来源 | 能拿到 | 拿不到 |
| --- | --- | --- | --- |
| 系统解析 | OS 解析器（`ToSocketAddrs`，5s 预算） | 是否解析、地址、耗时 | RCODE、TTL、上游 |
| 内核解析 | 控制器 `GET /dns/query?name=&type=`（mihomo 与 sing-box 同形 JSON） | RCODE、应答地址、TTL、控制器往返耗时 | 上游、缓存命中、内核内部耗时 |

两条路径都失败、只有一侧失败、内核未运行（`kernel_unavailable`）分别对应不同结论，
未观测不等于通过。

## 状态与失败处理

- 输入非法（空、非 ASCII、协议字符、超长标签）由后端拒绝并显示具体原因，输入保留。
- 内核未运行：只记录系统解析，结论明确写「内核未运行」。
- 检查期间再次提交会被禁用；检查后配置或内核变化时结果标记「可能不再适用」。
- 失败走统一 Notification（source `diagnostics-dns`），页面同时保留行内错误。

## 验证与证据

- 模拟：`node scripts/dev/verify-dns-probe.mjs`（生产组件 + IPC 桩），覆盖折叠/展开、
  非法域名、系统成功而内核 NXDOMAIN、内核未运行、历史 5 条上限与清除、复制摘要脱敏、
  深色 + 英文 + 最小窗口不横向溢出。截图见 `previews/`。
- 原生：隔离回环控制器上运行真实 mihomo `/dns/query`（`CROSSBOW_CORE_BIN` 忽略测试），
  `example.com` 返回 Status 0 且有应答，不存在域名返回 Status 3；sing-box 1.14.2 手动验证
  同一端点返回同形 JSON。未改系统代理、TUN 或用户配置。详见 `verification/native.json`。
