# #634 自定义组入口层级与弹窗工具条 · v02

日期：2026-11-22 · 关联 issue：#634（继承 v01 的能力模型）· 状态：已实现，待 PR 评审

## 问题（用户验收）

1. 「自定义组」按钮单独夹在页面标题与「策略组」标题之间，把来源导航向下推，且把"来源导航"与"管理操作"混在一起；空态时入口又换到 PageHead，两种状态定位不一致。
2. 组管理弹窗同一行的「刷新」比「添加组」矮（`size="small"` 28px vs 默认 32px），工具条与说明段落的层级也不清楚。

## 改动

- **入口**：管理入口移入左侧「策略组」标题行右侧（`.cb-node-nav-head`），删除独立的一行与 `.cb-node-custom-manage` 规则；空态/未运行/无配置仍保留在 PageHead 的动作区，且始终可用（可清理未激活来源的失效组）。它不进入右侧延迟测试动作组，避免"管理/测速"混淆。
- **弹窗工具条**：刷新与添加组统一默认尺寸（32px），主次靠 `variant="primary"` 区分，不再用两套规格。
- **层级**：顶部一行来源（小标签 + 名称），一行核心说明（创建组不自动改变出口），其余能力/路由/自动测试说明收进「说明与范围」折叠；列表行成员摘要最多 6 个、其余显示 `+N`，完整名单在 title 里。
- **小窗口**：编辑器底部动作改为 sticky footer，长表单在 880×560 下也能直接保存/取消。
- 保持不变：来源绑定、候选预览、重名/失效成员检查、保存竞态、失败保留草稿、被引用时禁止删除/改名；未改 #631 的 Modal 迁移（该 issue 仍开放，本 PR 不重复迁移）。

## 证据

- `scripts/dev/verify-custom-groups.mjs` 增加断言：入口位于 `.cb-node-nav-head`、旧的独立行不存在、工具条两个按钮同高、说明默认折叠；原有用例（预览、保存失败保留输入、来源变化禁存、中英文/明暗/最小窗口）全部保留。
