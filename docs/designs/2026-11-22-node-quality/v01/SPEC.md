# 节点质量历史 v01

2026-11-22 · #604 · **已实现，待用户原生/视觉验收**。

## 目标与布局

从节点页标题行的“质量历史”进入独立弹窗，不为每张紧凑节点卡片堆叠按钮。
上方依次为节点选择/刷新/单次测试、只记录节点页手动测速的说明和固定目标切换。
中间用四列对齐的定义列表展示成功率、P50、P95 和相邻成功延迟抖动；其次展示有效样本
与失败分类，再展示最近请求表。保留目标/方法说明及 UDP、吞吐未测标记。
底部记录开关、全局容量和清空操作固定可见，长历史仅在内容区滚动；清空需显式确认。

复用生产 `Dialog`、`Select`、`Button`、`Switch`、`ChoiceChip`、`Icon` 和 `cb` 主题变量。
沿用 Crossbow 当前 UI 规范；design-kb 的瑞士信息对齐/数据可视化原则和
emil-design-eng 的反馈/可达性用于检查细节，不另造品牌色或装饰图表。
无新增动效或图表库；数据不足保持 `—`，不给误导性的平滑曲线或“节点失效”结论。

## 设计检查

| 改前 | 改后 |
| --- | --- |
| 节点卡片仅有一次延迟 | 独立历史入口；卡片主目标延迟保持原语义 |
| 复核请求不能跨次查看 | 按固定 HTTP/HTTPS 目标分开查看成功、超时、控制器错误 |
| 无历史数据管理 | 有界本地记录、暂停和全局清空；操作失败保留真实状态 |
| 长弹窗可能藏住操作 | 固定底部隐私控件，内容区域滚动，880×560 可达 |

## 验收场景

- 中英文、明暗主题、1120×734 与 880×560；长记录、空目标、控制器失败。
- 打开历史不发探测；“测一次”传入固定目标，最多一个请求；运行中提供取消。
- sing-box 其他目标可查看未测状态，但不能发起对应请求。
- 更换节点不会显示前一个节点的迟到报告；配置/PID 变化关闭旧视图。
- 独立目标结果不覆盖主目标延迟；暂停写失败开关保留真实状态；清空之后在途观察不能回写。
- Escape 关闭并恢复焦点；清空有确认；不会触发节点选择。

## 复现与证据

`node scripts/dev/verify-node-quality.mjs` 使用生产 React + 脱敏 IPC，
`CB_QUALITY_EVIDENCE=<输出目录>` 可保存完整截图。`CB_QUALITY_BEFORE=1` 在基线工作树
运行同一脚本生成改前页面。源代码快照见 `source.zip`；生产源码在
`apps/desktop/src/pages/Proxies/NodeQuality.*`，数据与生命周期见 `docs/NODE-QUALITY.md`。

`verification/browser.json` 是模拟交互结果，`verification/native.py` 重放等价控制器请求，
复用 #503 隔离 DIRECT-only 夹具，并使用独立显式代理业务探针测量前/同期的成功率和
延迟。它不执行 Tauri IPC 或原生 UI，也没有修改系统代理/TUN/DNS，不证明物理出口。
脚本重放与 Rust observer 分别验证，不能将其合并称为原生客户端验收通过。

UDP、吞吐和独立 TCP/TLS 分层诊断按 issue 分组留待后续 PR；#604 保持开放。
