# 桌面验收：可复跑场景与实机记录

本文回答两个问题：**下次怎么用同一条命令复跑关键桌面场景**，以及**某个版本在真实机器上验收到了哪一步**。
模拟结果与原生结果按 [QUALITY.md §5](QUALITY.md) 分开记录，不相互替代。

## 1. 可复跑入口（模拟环境）

```sh
pnpm install                        # 首次或依赖变更后
pnpm verify:desktop                 # 全部场景（headless）
node scripts/dev/verify-scenarios.mjs --scenario 2   # 只跑一个场景
node scripts/dev/verify-scenarios.mjs --headed       # 显示浏览器
```

- 工作方式：vite dev 按生产代码原样渲染页面；`addInitScript` 注入
  `__TAURI_INTERNALS__` 桩（`scripts/dev/verify-lib.mjs`），IPC 夹具由场景通过
  `window.__cb` 控制迟到、失败与事件顺序。playwright-core 只驱动系统已装浏览器
  （`CB_CHROME_BIN` 可指定），不下载浏览器二进制。
- **脱敏边界**：夹具数据全部为 `stub.invalid` 假数据，不操作真实订阅、内核、
  系统代理或 TUN；入口只用于开发和测试。启动期出现未登记的 IPC 命令会直接判失败，
  防止夹具缺口静默通过。
- 失败现场（截图、IPC 调用计数、控制台错误）写入临时目录并打印路径，不进仓库。
- CI 接入：`.github/workflows/build.yml` 的 frontend job（ubuntu 预装 Chrome），
  纯前端改动必跑；耗时原生场景不进 CI，按下节实机记录执行。

### 场景清单

| # | 场景 | 驱动点 | 固化的回归 |
