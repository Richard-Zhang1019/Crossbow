# 桌面验收：可复跑场景与实机记录

本文回答两个问题：**下次怎么用同一条命令复跑关键桌面场景**，以及**某个版本在真实机器上验收到了哪一步**。
模拟结果与原生结果按 [QUALITY.md §5](QUALITY.md) 分开记录，不相互替代。

## 1. 可复跑入口（模拟环境）

```sh
pnpm install --frozen-lockfile       # Node.js 22+、pnpm 9
pnpm verify:desktop                 # 全部场景（headless）
pnpm verify:desktop --scenario 2   # 只跑一个场景
pnpm verify:desktop --headed       # 显示浏览器
```

- 工作方式：vite dev 按生产代码原样渲染页面；`addInitScript` 注入
  `__TAURI_INTERNALS__` 桩（`scripts/dev/verify-lib.mjs`），IPC 夹具由场景通过
  `window.__cb` 控制迟到、失败与事件顺序。playwright-core 只驱动系统已装浏览器
  （`CB_CHROME_BIN` 可指定），不下载浏览器二进制。
- Vite 使用临时回环端口和独立缓存。模拟页面只允许连接该回环服务，夹具不调用真实订阅、内核、系统代理或 TUN。
- 未注册 IPC、页面异常和非回环请求会让场景失败。失败记录包含场景、提交、浏览器版本、视口、截图、IPC 计数和控制台错误。默认写入系统临时目录，可用 `CB_VERIFY_ARTIFACTS_ROOT` 指定目录。
- CI 在纯前端改动时用 frontend 作业，在同时有 Rust 和前端改动时用 Linux foundation 作业。两条路径共用命令，失败时上传 `desktop-scenario-evidence`。原生验收单独记录。

### 场景清单

| # | 场景 | 驱动点 | 固化的回归 |
| --- | --- | --- | --- |
| 1 | 配置快切忽略同名节点旧结果 | 从页头切换配置，新快照渲染后释放旧测速应答 | 同名节点保留新快照延迟，后端收到结束旧任务的请求 |
| 2 | 测速取消后停止派发 | 测速期间等待周期刷新，释放第一批、取消，再释放迟到结果 | 刷新后继续派发，取消后派发数冻结，已完成结果与未完成的取消状态保留 |
| 3 | 诊断原样本和恢复样本及导出白名单 | 故障证据、过期与复检事件、预览与复制按钮 | 两种故障状态正确展示，复制结果与白名单摘要一致 |
| 4 | 默认和最小窗口的焦点与滚动 | 使用 Tauri 配置的两种尺寸，遍历中英文和明暗主题的八种组合 | 导航可点，页脚可见；Tab 到端口编辑时滚动到视口，Enter 打开，Escape 恢复焦点 |

中英文与明暗主题经 `ui://lang` / `ui://theme` 事件热切换（设置页同一路径），无需重载。
