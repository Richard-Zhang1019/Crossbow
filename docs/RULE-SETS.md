# 独立规则集（#571）

配置 → 规则集 → 添加规则集：填写名称和 HTTP(S) URL、匹配类型、更新周期及目标策略。第一次下载并完整校验成功后才保存、启用；新规则不依赖机场订阅。目标可选 DIRECT、REJECT，以及当前有效配置里的节点/策略组，不虚构名为 PROXY 的内置策略。

## 匹配顺序与生命周期

固定优先级：应用进程规则 → 用户排序的规则集 → 订阅规则。菜单提供编辑、立即更新、上移、下移和删除；开关即时启停。运行中改动走现有配置事务（渲染、热重载或重启、失败回滚）；应用未运行内核时只保存配置，不主动打开代理。URL、behavior 不变的编辑复用缓存，离线也能换目标或调整周期。

配置和最后成功的规则缓存共同保存在本地 store 文件中，不单独覆盖供正在运行的内核读取的文件。订阅/引擎切换保留规则集；目标消失时保留条目、跳过注入，页面明确标示。重新选择有效目标后恢复。旧 store 通过 serde default 兼容，无规则集时保持既有渲染行为。缓存不会自动包含在当前仅搬迁 Profile/覆写的便携导出包中；整库快照包含这些数据。

## 支持格式

- YAML/JSON 的 `payload` 字符串数组，或每行一条的 UTF-8 文本；支持空行、行首 `#` / `//` 注释，重复条目去重。
- `domain`：精确域名、`+.example.com`（含根域名）、`.example.com`（不含根域名）、完整标签通配符如 `*.example.com` / `*.*.example.com`。单级 `*` 与多级 `+` 不混淆；sing-box 使用等价域名字段或正则。
- `ipcidr`：有效 IPv4 / IPv6 CIDR。
- `classical`：DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6、SRC-IP-CIDR、DST-PORT、SRC-PORT、NETWORK（tcp/udp）、PROCESS-NAME。条目不带策略目标，整份规则集统一挂载到所选策略。
- 本轮不支持 MRS/SRS 二进制、GEOIP/GEOSITE、逻辑/嵌套 RULE-SET、端口范围、`no-resolve` 等附加参数或任意表达式。为保证双内核一致性，任意不支持/无效条目导致整份拒绝，保留旧缓存；不默默忽略条目。

最多 32 个规则集，每份下载上限 2 MiB / 50000 条规则；URL 去除 fragment 后规范化去重。URL 不接受内嵌用户名密码；错误不回显源 URL、token 或原始条目。自定义 HTTP(S) 规则源由用户选择，不调用转换服务。

## 后台更新

复用现有 30 秒 scheduler tick，每次最多更新一个到期规则集，避免多个慢源占满后台线程。周期由编辑器指定（后台支持 300–604800 秒）；失败重试复用 15 分钟起、封顶 6 小时的指数退避。禁用条目不安排后台下载。

应用进程（包括正常托盘运行）存活时调度生效；轻量退出会结束 UI/调度进程，独立继续运行的内核使用旧缓存，重新打开应用后恢复调度。

成功更新静默：内容未变只保存更新时间；内容变化才提交配置事务。下载、格式校验或应用失败都保留旧规则和缓存，失败走统一 Notification；成功重试解除对应警告。页面显示“更新失败 · 继续使用缓存”。网络请求不持有 store/core 锁。

下载开始时快照规则集，提交时比较完整条目。编辑、禁用、删除、新缓存或手动成功更新会让旧请求失效。后台失败通知和退避发布也与配置事务串行校验，避免在新操作成功后又提示旧失败。

## 两个内核

原生 sing-box 配置保留其 outbounds/route 结构，不经 Clash 转换器；覆写或旗帜补全输出 YAML 时再规范化回 JSON。mihomo 使用 inline `rule-providers` + `RULE-SET`；sing-box 使用 inline `route.rule_set` + 按排序的 route rules。内核从本地缓存生成的配置消费规则，无需在启动/重载时下载远程源。这样离线启动仍有上一份规则，也不会出现两个内核各自下载到不同版本。

依据：[mihomo 规则集合](https://wiki.metacubex.one/config/rule-providers/)、[mihomo 域名通配符](https://wiki.metacubex.one/handbook/syntax/#_10)、[sing-box rule-set](https://sing-box.sagernet.org/configuration/rule-set/)。

## 验证与边界

- core 覆盖文本/YAML、拒绝坏条目、通配符语义、顺序、启停、目标失效、序列化、规则名冲突；回环 HTTP 验证有效新缓存与坏更新拒绝。
- 后端覆盖迟到请求不能覆盖编辑/禁用/删除/新缓存，以及周期/退避/禁用调度。
- 生产组件 + IPC 桩覆盖新增、编辑失败保留、成功重试、排序、开关、空数据、明暗/中英文、最小窗口。
- 单独启用的原生用例：两个真实内核配置校验（含 classical/REJECT）；临时端口实际 HTTP 请求，核对命中目标策略和禁用后的 DIRECT chains。未修改系统代理、TUN、用户订阅或已安装应用。
- 仍待用户环境验收：实际社区大规则源的长期更新、网络切换/托盘运行，以及 Windows 完整流程。回环路由验证不代表远端机场可用或系统代理/TUN 验收通过。
