# 域名/IP 用户规则（#605）

配置 → 用户规则，支持 `DOMAIN`、`DOMAIN-SUFFIX`、`IP-CIDR`（IPv4/IPv6）。规则保存为结构化字段 `user_rules`，旧配置缺省为空，不修改订阅原文，不依赖覆写链，安全模式仍保留。

## 优先级与解释

规则模式下：**进程规则 → 用户规则（列表从上到下）→ 独立规则集 → 订阅规则**。上移/下移改变实际顺序；停用不删除记录。目标失效时保留规则并显示不可用，渲染时跳过；目标恢复后重新生效。编辑器只提供当前有效配置中的目标及 DIRECT/REJECT。已失效但未改变的记录不会阻止编辑其他规则。

`DOMAIN` 精确匹配，`DOMAIN-SUFFIX` 匹配本域及子域，不匹配仅字符串相似的域名。sing-box 使用 `domain` 和带点 `domain_suffix` 的 OR 匹配，并排除显式 direct/global Clash 模式；mihomo 使用原生规则。IP-CIDR 规范化网络地址，mihomo 使用 `no-resolve`；规则本身不额外触发 DNS。全局/直连模式不应根据用户规则推断出口。

静态提示只识别较早且有效的域名后缀覆盖后续域名条件，不声称检测全部规则冲突、进程匹配、网段交集或 DNS 路径。它不是内核匹配模拟器。**连接详情的命中规则和出口链是内核实测元数据**，与规则列表的意图/静态顺序区分；诊断的配置渲染检查使用同一渲染管线，不另外推演匹配结果。

字段映射依据：[sing-box Route Rule](https://sing-box.sagernet.org/configuration/route/rule/)。当前受控验证基线为 mihomo v1.19.32 / sing-box v1.14.2，其他版本不据此保证。

## 编辑与失败保护

- 连接详情的“创建域名/IP 规则”只带入精确域名或单 IP 的 /32、/128，不自动创建后缀或宽网段；必须人工确认。
- 域名转小写/IDNA，拒绝 URL、端口、通配符、无效标签；CIDR 规范化后检测重复。同类型同值只能有一条，含停用记录。最多 512 条。
- 保存整份有序列表时携带读取的原列表，后端在配置事务内比较，拒绝过期编辑；新规则/变更目标再次按当前配置校验。
- 复用 `commit_config_change` 的渲染、热重载和落盘回滚，不作 UI 乐观更新。失败通过统一 Notification，编辑内容保留；过期编辑应取消、刷新页面并重新检查后提交。
- 删除在编辑弹窗中；启停和排序直接在列表操作。持续连接不会因新规则自动重连，验证出口请新建请求。

## 验证边界

原生脚本经公开 `render_config` 生成配置，用临时回环 HTTP 源站/代理响应区分直连与指定策略，覆盖双内核的精确/后缀/相似域名、IP、顺序、停用和删除，共 22 个真实路由用例。没有启用系统代理/TUN，没有访问公网或真实订阅。

生产 React + IPC 桩覆盖排序、启停、保存失败保留输入和连接 IPv6 候选导航；截图不是原生 IPC 验收。用户实际配置的热重载/失败回滚、订阅更新、系统代理/TUN 和其他平台仍须实机验收。详细证据、源稿及复现见[设计归档](designs/2026-11-22-user-rules/v01/SPEC.md)。
