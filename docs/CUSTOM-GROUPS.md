# 自定义策略组（#606，首版能力模型）

入口：节点页侧栏「自定义组」。订阅自带组继续用于查看/选点；此入口只管理用户新增的组意图，不修改订阅原文或已有组。

## 操作与行为

1. 激活一个包含 Clash 格式内联节点的配置，打开自定义组，添加组。
2. 填写唯一组名，选择手动选择或自动测试。
3. 成员可多选当前来源的具体节点，也可设置一个不区分大小写的字面包含条件（非正则）。预览经过覆写、组注入、旗帜补全及当前内核转换后的最终成员。
4. 自动测试组设置 HTTP(S) 测试 URL、间隔（30–86400 秒）、容差（1–65535 毫秒）。预览不测速、不下载；保存后运行中的内核会按该 URL 周期访问网络。
5. 保存使用现有配置事务：运行中的内核应用新配置；失败沿用既有回滚流程并用统一通知报告，表单保留输入。
6. 创建组**不改变已有流量路由**。在用户规则/进程规则中明确选择新组作为目标，或在已有支持的规则集中指定它，命中流量才走此组。节点页可查看该组并手动选择成员；自动测试组由内核择优。

每个组以 `profile_id` 绑定来源，并单独保存于 `StoreSchema.custom_groups`。应用重启、同一来源更新不会覆盖这些意图。切换来源后仅注入当前来源绑定的组；未激活/已移除来源的意图仍列出，可以清理，编辑需先激活其来源。

## 方案比较

- 最小实现：把生成的 `proxy-groups` 作为 Merge 覆写保存。可复用编辑器，但难以区分订阅组与用户意图、解释更新后的失效成员及保障重名/引用校验。
- **最佳方案：独立持久化组意图，渲染时解析并注入。** 原始订阅保持不变，可在保存、更新、转换时统一验证；来源、成员方式和最终候选均能解释。首版只开放两内核可共同表达的子集，复用现有运行时事务。
- 完整 provider/多订阅/嵌套/链式图编辑器会扩大下载生命周期、凭据和循环检测范围，后续单独实现。

## 有效性与失败边界

- 最多 32 个组，每组最多 4096 个显式成员；组名不得与来源节点/组或内置目标重名，同一来源组名不能重复。名称过滤上限 256 字节。
- 仅具体内联代理节点可成为成员，排除 DIRECT/REJECT/COMPATIBLE/GLOBAL 及 direct/reject/dns 类型。禁止嵌套组，因此自引用、相互引用都不能保存；不隐式添加 DIRECT 或其他兜底。
- 显式成员消失会报失效引用；名称过滤随来源更新重新计算，空结果报错，不静默只保留部分成员。更新失败时现有配置事务保留旧的有效配置，原意图仍保留；可在日志/通知查看更新失败，在编辑器修正或删除后重试更新。
- 来源失效/下载失败复用现有订阅缓存与更新流程；组编辑本身不下载来源。来源/覆写/内核/DNS/安全模式变化会令旧上下文失效；保存还比较完整组列表，防止旧窗口覆盖新修改。
- 删除/改名之前检查用户规则、进程规则、规则集和有效来源配置中的直接引用；被引用时先迁移规则。来源配置的复杂脚本语义仍由现有覆写/内核校验负责。
- Clash 来源可在 Mihomo 与 sing-box 之间转换；不支持或无法等价转换时拒绝保存。首版不编辑原生 sing-box JSON 的节点来源，不开放跨订阅/provider 管理、嵌套组或链式代理。
- 本功能为本机持久化能力；配置包 v2（#607）暂未携带 `custom_groups`，恢复到另一台机器需重建这些组及其引用。后续扩展包格式时应一并映射来源 ID、校验引用，不能只复制名字。

## 实现与验证入口

- 模型/解析：`crates/crossbow-core/src/custom_groups.rs`；注入位置：覆写之后、旗帜补全和内核转换之前。
- 命令/事务：`apps/desktop/src-tauri/src/commands/custom_groups.rs`，共享配置变更锁、持久化及失败恢复流程。
- UI：`apps/desktop/src/components/CustomGroups`，复用 Dialog、Button、Input、Select 多选和 Notification。
- 生产页面模拟：`node scripts/dev/verify-custom-groups.mjs`。
- 双内核受控验证与截图/源稿见 [v01 设计与验收档案](designs/2026-11-22-custom-groups/v01/SPEC.md)。模拟 IPC 不等于 Tauri 实机验收；未替用户切换系统代理或 TUN。
