# Crossbow 迭代路线图

> 基于 2026-10-04 M0（tag `m0.1`）交付后的规划，按「日常使用价值优先」排序。
> 每个里程碑完成即打 tag；范围可在实际使用反馈中调整。
>
> 平台：macOS（现役）→ Windows（M1.5）→ iOS（M2）。TUN 暂缓，
> 重启触发条件：出现「某应用流量不走代理」的真实困扰（见 DESIGN.md）。

## M1 · macOS 完整版（约 4–6 周）

### M1.0 正式打包与自更新（~1 周）✅ 2026-10-04 · 已发布 [v0.2.0](https://github.com/Richard-Zhang1019/Crossbow/releases/tag/v0.2.0)
*目标：摆脱终端，像正式产品一样安装使用。*
- ✅ `tauri build` 产出 .app（62MB，mihomo sidecar 随包分发），打包版启动冒烟通过
- ✅ 内核缺失自动下载（gh-proxy 镜像优先，锁定 v1.19.32，大小校验）
- ✅ updater 基础设施：签名密钥对、createUpdaterArtifacts、应用内「检查更新」（端点待发布渠道）
- ⏭ 待办：bundle identifier 从 com.crossbow.app 迁移（.app 后缀冲突告警，需同步迁移数据目录）
- ⏭ 待办：dmg 打包（无公证环境的 bundle_dmg.sh 问题）与发布渠道（GitHub Releases + latest.json）
- 验收：双击 .app 日用一整天，无终端依赖 ← *请用户验收*

### M1.1 订阅生命周期完善（~1 周）✅ 2026-10-05
*目标：订阅不再是「导入一次就不管」。*
- ✅ 自动更新调度：后台线程 30s 扫描，到点刷新，失败保留旧内容 + 指数退避重试（15min×2^n 封顶 6h）
- ✅ 配置卡片：间隔选择（关/6h/12h/24h）、下次更新时间、失败原因展示
- ✅ 更新结果落库（Profile.last_update，向后兼容）
- 验收：修改远端订阅内容，到点自动生效；远端挂掉不影响现有使用 ← *请用户验收*

### M1.2 可观测性与诊断向导（~1.5 周）✅ 完成，随 [v0.3.0](https://github.com/Richard-Zhang1019/Crossbow/releases/tag/v0.3.0) 发布
*目标：把「为什么不通」从用户提问变成一键自检。*
- ✅ 网络诊断向导（独立页）：内核/控制器/配置渲染/端口监听/系统代理指向/代理连通（204 探测）/直连 DNS 七项，失败项带修复按钮并自动重跑
- ✅ 首页「当前出口」实装（MATCH 规则 → 组 → now 链解析，带延迟与决策链）
- ✅ 连接页单连接断开；首页状态灯三态（红/绿/灰）
- ✅ 连接页按进程聚合（双视图切换，点击进程下钻过滤）+ 首字母圆形进程图标（M1.2 全部完成 2026-10-05）
- 验收：模拟断网场景，向导能定位到具体环节并给出可用修复动作 ← *请用户验收*

### M1.3 配置能力与进阶（~1.5 周）✅ 2026-10-06 完成
