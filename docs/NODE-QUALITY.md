# 节点质量历史（#604，第一阶段）

节点页 → **质量历史**。选择节点和目标查看最近观测；“测一次”只测当前固定目标一次，
不会为补齐其他目标的数据发请求。沿用最多 10 个并发、单次请求最多 7 秒、批次最多
120 秒的预算；每批至多接受 4096 个不同节点，重复调用不会新增请求。打开/刷新历史、选择目标和节点只读本地数据。
日常节点页单节点/整组测速沿用原流程：mihomo 先 Google HTTP，目标超时才复核
Cloudflare HTTPS；sing-box 仅 Google HTTPS。托盘测速和自动选路历史暂不纳入此统计。

## 方案与指标

页面内存缓存是最小方案，但不能跨次查看。**最佳方案**是后端保存有界本地观察，复用
已有批次、并发、预算、取消和配置代保护；不引入后台测速或新的自动选路算法。

- 每个目标独立统计。HTTP/HTTPS 是请求级观测，不能解释为独立 TCP/TLS 故障诊断。
- 成功率 = 成功 /（成功 + 目标超时 + 请求失败）。控制器异常单列，不参与分母；
  取消、跳过、未知节点和已失效配置的迟到结果不记录。
- P50/P95 使用成功延迟的 nearest-rank 分位数；抖动为时间顺序中相邻成功延迟差
  的绝对值平均数（整数 ms）。不跨目标、配置或引擎混算，不将失败填成 0 ms。
- 无有效探测时成功率为 `—`；无成功样本时分位数为 `—`；成功不足 2 次时抖动为 `—`。
  有效探测不足 5 次显示样本不足提示，不判断节点永久失效。
- 最近记录展示至多 12 条；统计基于当前保留的至多 64 条，而非全部历史累计。
- 不修改接管开关、节点选择或策略。指定目标结果不覆盖主目标卡片/排序延迟；mihomo
  控制器只返回其他目标历史时，也不会将其当作主目标延迟。
- sing-box 没有同等的分 URL 选路历史，拒绝其他目标，避免将异站结果注入同一选路缓存。

## 边界与隐私

文件位于应用数据目录 `node-quality.json`，使用共享私有原子写入（Unix `0600`）。
不上传；不持久化节点名、订阅 URL、节点地址、凭据或错误原文。仅保存配置/节点标识
的 SHA-256、固定目标枚举、时间、结果分类和延迟。标识用于隔离观测，不是对网络层
匿名性的承诺。scope 包含活动配置 ID/内容、引擎、绑定覆写及顺序、DNS 设置；更换
配置或引擎后不混入旧结果。订阅 provider 在相同来源/节点名下更换实际服务器的情况
尚不能识别，不能将这些观察当作物理服务器的长期身份；可手动清空。

最多保留 **7 天、8192 条、512 个节点-目标桶、每桶 64 条，文件上限 2 MiB**。
启动、记录和查询时裁剪；查询会将过期裁剪结果落盘。应用不运行时不执行文件清理，
恢复使用后清理；没有为此增加常驻网络任务。批次结束或查询时保存；进程意外退出
可能丢失当前批次尚未保存的观察，不影响代理配置。

记录开关针对所有节点，默认记录节点页手动测速；关闭后仍可测速和查看已有历史。
暂停/恢复和清空都会使在途观察失效，恢复后需重新测速。清空有二次确认，保留原
暂停状态。写失败不显示操作成功，重新读取真实偏好；若原子替换已提交但目录同步失败，
内存与实际文件对齐并仍报告失败。损坏/未知版本/超大历史不覆盖原文件，显式清空后重建。

## 验证边界与后续

- Rust：目标分别记账、超时复核请求数、取消不发布、控制器排除、样本少、容量/过期、
  持久化/文件权限、暂停/清空隔离、失败偏好及主目标回流回归。
- 浏览器：真实 React + 隔离 IPC，运行 `node scripts/dev/verify-node-quality.mjs`，
  覆盖无额外探测、固定目标、取消、写失败、清空、sing-box 限制、中英文/明暗/最小窗口。
  CI 的两处前端场景清单均纳入此脚本。
- 真实双内核与独立显式代理业务探针：见设计档案 `verification/native.json` 和同目录
  可复跑脚本，复用 #503 夹具。该检查重放等价控制器请求，不是 Tauri IPC/原生 UI 或
  系统代理/TUN 接管验收，也未证明公网物理出口。记录 P50/P95、成功率和请求数，不
  以单次小样本推断“无干扰”。

按 issue 的 PR 分组，这一版只完成质量历史与有限 HTTP/HTTPS 指标；UDP、有限流量/时长
吞吐测试，以及独立 TCP/TLS 分层诊断仍待后续 PR，界面明确标为未测，#604 保持开放。
